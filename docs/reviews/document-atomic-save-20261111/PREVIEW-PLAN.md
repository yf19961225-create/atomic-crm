## 单事务执行

使用既有受控迁移连接及 Ledger 机制，`BEGIN` → 精确 SQL → 检查对象、owner、临时 SET/CREATE 撤销、角色成员关系 → 插入本版本 Ledger → `COMMIT`。任一步失败完整回滚，不自动换账号、不重跑历史、不放宽权限。SQL与Ledger必须同一事务，不能分别成功。

数据库验收：1表、4 revision列、9函数、12触发器、13策略及精确ACL；原49类业务表指纹保持（新列独立验证）；客户端不可直接写回执/任意修改revision。两有效用户、禁用、匿名、无CRM身份分别执行真实REST/RPC测试，只使用本轮QA身份和记录。

## 真实 Preview 验收矩阵

- Quote / PI / Order / 独立及订单关联 Packing：创建→至少两行→修改/移除/新增→保存→刷新重开，保留编号、来源、金额、小数及快照。
- 每类两独立用户打开同revision，A保存，B被PT409拒绝且输入保留；随后主动重新读取/编辑。
- 同request重放只返回第一次结果；异内容同request拒绝；用户间回执不可读取。
- 浏览器拦截响应造成“服务端提交、客户端丢失”，查询恢复；未提交断网后显式同ID重试；刷新后恢复原payload；原A未知后编辑B，查询A不覆盖B。
- Order：已有QA收款、定金阶段、币种冻结、受控作废/删除、客户归档及工作台通知；不把付款创建并入普通订单保存。
- Packing：箱数×箱规、重量、CBM、跨装箱单剩余量并发；原有产品行被生产/装箱引用时保留ID和约束。
- 报价转换PI/Order及询盘转报价：来源版本及幂等，原编号生成规则不变。
- 内联状态、客户送货日期、订单生产要求/唛头：沿用新事务/CAS；工厂交期原独立RPC不改。
- 1440/1280/390页面、键盘录入、图片及搜索仅做受影响必要回归。
- QA清理仅走受控删除；持久保存回执及受保护金融/审计证据保留并记录ID，不强删。
