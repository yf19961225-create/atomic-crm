# Design System 2.0 全站实施与验收计划

## 基线与边界
Production/远端工作分支 a62cb914cac94ceb72789110d22b70b990032776；试点 c8fd0b64be2299cd0c4874e24ac7053f81633818 在其上增加两个 UI 提交。独立分支 codex/design-system-v2-fullsite。仅 Preview；不改变业务计算、API、RPC、数据库或导出模板。

## 实施顺序
1. 完整路由、组件和弹层清单；复用已批准的 Inter/Noto、蓝灰白、24/18/14px 规范。
2. 订单/PI 明细延迟加载的失败测试；复用报价单 readyForEdit 保护，保存算法不变。
3. 全站共享 scope、页面标题/工具栏/数据表/表单/详情/分页/空状态语义样式；Portal 单独覆盖；避免影响 FullCalendar 和日期网格。
4. 逐模块应用语义组件类，修复长内容和移动端局部滚动；不以全局 CSS 代替模块适配。
5. 完整前端测试、typecheck、lint、Preview build/PWA；精确源码部署至现有 Vercel 项目，确认仅 Preview 数据源。
6. 按清单在 1440/1280/390 验收，截图必须为加载完成的实际页面。业务写入仅明确 QA 数据，保留受保护记录。
7. 记录完整/未完成/问题项、证据、GitHub 同步状态和最终 SHA；不发布 Production。

## 风险与验收
宽表允许内部滚动，不允许页面整体溢出。固定列规则只用于其对应单据表。空值、长中文/SKU、20+产品、键盘焦点、日期/弹层、刷新/取消/QA保存需验收。所有未执行检查保持待验收，不报 PASS。GitHub 之前 push 审批阻断不可绕过。
