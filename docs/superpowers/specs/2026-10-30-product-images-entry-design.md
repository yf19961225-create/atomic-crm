## 目标与基线

从已上线 `6f11b09acae398766c37a0b162370e048e01a6ae` 开始，在独立分支 `codex/product-images-entry-workflow` 完成全量图片审计、共享图片回退、Enter 连续录入及实时搜索。最终仅部署隔离 Preview，等待 Production 授权。

优先解决共性问题，禁止 SKU 特判、修改历史快照、CMS 图片或真实单据。保留数量、金额、箱规、装箱来源、付款待办及网站询盘逻辑。不需要数据库结构变化；如发现必须迁移，停止报告。

## 图片加载设计

1. 单据行优先尝试原快照，成功时不替换。失败或缺失后，查找精确 SKU 的产品库候选，再尝试精确 SKU 官网候选。产品库查询结果必须逐项严格比较 SKU，不能用模糊搜索第一条替代。无法可靠匹配则跳过。
2. 搜索缩略图与现有产品库缩略图保持官网精确 SKU 首图优先、Sanity 后备；官网首图也必须实际加载成功。此顺序减少已知失效 Cloudinary 首图的等待，不改变 Sanity 多图顺序或图库内容。
3. 统一加载器接受 SKU/产品身份、候选数组及尺寸样式；去重后每个 URL 在本次身份生命周期最多尝试一次。通过加载成功事件及有效自然尺寸确认；未加载时隐藏原生破图图标，显示加载状态，全部失败显示“暂无图片”。占位不计为图片恢复。
4. 建议单候选超时 10 秒（实现者可按浏览器证据小幅调整并记录）；超时进入下一候选。清理定时器，忽略旧身份、旧候选的 load/error 回调。切换 SKU、快照或搜索结果立即重置显示，不残留旧图。
5. 精确 SKU 元数据请求共享缓存、请求去重；短时失败缓存防止重新渲染不断请求，页面刷新/缓存到期允许恢复。不将永久失败状态写入数据库。候选扩展不重试已失败 URL。
6. 官网多个候选可在既有图片 API 中增加兼容的可选数组字段，保留旧单图响应与调用者；仅在审计证明存在需要时实施。不能破坏原产品图库顺序。
7. 产品选择沿用原快照结构；有已验证显示候选时可将其作为新行图片来源，异步回退不改写已保存快照。没有已验证候选仍可选择产品，行组件安全恢复图片。
8. 覆盖商业表格、PackingItemsGrid、产品搜索及复用图片组件的选择页面；生产/询盘等其他页面仅审计影响，不扩大业务修改。

## 实时搜索

- 使用当前紧凑搜索框及结果 Portal，不增加第二个输入框或大面板。
- 约 250ms 防抖；按钮/Enter 可立即查询。保留服务端现有完整 SKU、规范化 SKU、前缀、包含及名称排序。
- 输入变化立即使旧结果不可选择；使用请求代次及取消机制拒绝旧响应。Sanity 结果先呈现，官网候选补充不能阻塞文本列表。
- 中文组合期间不查询/不选中/不新增行；Esc 关闭并使在途结果不能重新打开，下一次输入或明确搜索可重新打开。
- 上下键、Enter、鼠标与清空保留；无结果显示明确提示。不得自动选中模糊匹配。
- 鼠标选择保持 preventDefault 和 selection guard，避免 blur 先提交 manual SKU；异步选择只提交当前产品一次。
- 填充仍走各单据现有回调，覆盖价格、数量、手工规格的情况先用测试锁定，不能借此重置用户有效编辑。

## Enter 与装箱边界

Quote / PI / Order 复用现有 advanceVisibleRow。完成现有必需产品信息后，在适用单行输入上 Enter 聚焦下一行；已有下一行优先复用，末行才创建一个空白草稿。不能将单价留白判为新增必填。空白或无有效产品行不得继续制造空行。重复键、pending focus、中文组合、候选选择与异步提交均需防重入。textarea Enter 只换行；输入内 Enter 不提交整单。

用户明确批准装箱限制：

- 关联订单：保留自动导入全部剩余产品；搜索只定位当前单已有产品；Enter 聚焦下一条可编辑产品，不新增行、不允许从产品库引入其他产品。最后一行保持原位，避免隐式循环或新增。
- 独立装箱：实时产品库搜索并新增；SKU 去重沿用现有规则。完成末行后 Enter 聚焦下一条可用产品录入入口，支持下一款搜索；如采用内联空白录入行，其仅为 UI 草稿，选中产品前不得进入保存/计算。实际布局细节由实现者以最小改动决定并在 Preview 展示。
- 原新增按钮、Tab、取消、dirty lifecycle、保存、数量/CBM/重量计算保持。
