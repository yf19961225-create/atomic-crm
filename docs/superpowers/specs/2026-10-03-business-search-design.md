# Approved business search and Production deletion design

User approved this design in chat on 2026-10-03 and explicitly authorized writing the implementation plan and continuous execution through Preview acceptance. No additional planning approval is needed.

Production deletion extends romiku_delete_record(kind,record_id), SECURITY DEFINER fixed empty search_path, authenticated and auth.uid checked, static kinds. Followups block with exact count and readable HAS_DOWNSTREAM. Otherwise detach manual_tasks.production_order_id, remove own items/header, preserve Order/items/snapshot and numbering counter. Existing deletion semantics remain. All five document detail headers expose small upper-right ellipsis menu; reuse confirmation, safe errors, redirects/cache invalidation.

Search uses indexed stored generated explicit business text columns, pg_trgm GIN indexes, missing relationship B-tree indexes, and SECURITY INVOKER authenticated-only romiku_global_search(query text, resource_types text[], limit integer, offset integer, filters jsonb). No dynamic SQL/table names, whole JSON/raw_payload text, external services or client-side all-record searching. Search before pagination. Restrict resource_types to formal_customer,outbound,website_inquiry,quote,pi,order,production,packing; filters to status,order_id. Validate malformed parameters. Literal % _ backslash are escaped. Phone formatting (+ - spaces parentheses) normalizes to digits with country code retained; original values stay unchanged.

Ranking: document number/SKU exact, then company/contact/email/normalized phone exact, then prefix/partial; newest date, UUID tie-break. One document once regardless of matching items. All resource groups independently paginated/countable. Archived visibility unchanged.

Commercial headers cover number/date/status/currency/notes, explicit counterparty fields (company,name,brand,business name,contact,phone,WhatsApp,email,country,region,city,address and saved aliases), requirements. Own items cover SKU,customer_code,name,description,specification,requirement,notes. Source visible names/numbers are an additional labeled channel, never replacement for saved snapshots. Production uses ONLY its own item snapshots for product matching; source Order saved buyer snapshot and number allowed (not source Order products). Packing uses own seller/buyer/item snapshots plus source Order number; include Unit. Formal customers/outbound include contacts and explicit business fields; website inquiries include saved items and message/processing notes. Do not use current Product Library or Sanity. Do not change historical snapshots or exporters.

RPC response: {groups:[{resource_type,total_count,limit,offset,has_more,items:[{id,title,subtitle,matched_fields:string[],rank:number}]}]}. limit/offset applies per group. Default 25/max50; global requests 5 for all eight groups, then loads each group independently; lists request one type/25. Group entries exist for zero matches. Empty query returns groups with no search results; lists use existing ordinary listing when empty. Sorting remains RPC order. Modules batch hydrate only returned page IDs using existing resources/totals, then reorder by RPC IDs; at most two requests, never N+1. Shared React Query key prefix romiku-search permits deletion invalidation. Navigation global search /search, document routes existing, other resources ?record=id.
